# 09 扩展手册（改哪里、怎么验）

> **读者**：拿到一个具体需求（"加个协议 / 加个变量 / 加个报警规则 / 加个页面 / 加个 MCP 工具…"）、
> 想知道**最少改哪些文件、按什么顺序、怎么证明没改坏**的人。
>
> 每个配方都按：**目标 → 改动清单（按提交顺序）→ 陷阱 → 验证**。行号/类型名以当前代码为准，改完用 grep 复核。

---

## 通用纪律（所有配方都适用）

1. **先跑基线再改**：`dotnet build` 0/0、Domain.Tests 43/0、Infrastructure.Tests 292/0、Verify 6 PASS。
   改完回归到同样数字，才算"没改坏"。
2. **一条改动一个关注点**：加协议不要顺手改报警算法；否则出问题分不清是谁。
3. **改运行目录的 `settings\*.json` 前备份**（`*.json.bak`），它是现场配置，不是源码。
4. **Kill 再 build**：`taskkill /IM KyjScada.App.exe /F`，否则 MSB3027 锁文件。
5. **`Scale/Offset` 当前不生效**——任何配方里如果要做工程量换算，先读 02 篇第 11 节。

## 配方 1：新增一个 Modbus 变量（最常见，纯配）

**目标**：在现有设备的某个组里加一个点，能采、能显示、能归档、能报报警。

### 改动

1. **备份** `bin\Debug\net8.0-windows\settings\<对应>.json`。
2. 用界面「配置编辑器」（推荐）或手改 JSON，在目标 `GroupList[i].VarList` 里加：

```json
{
  "Start": "76",                       // 绝对偏移，必须落在组 [基址, 基址+Length) 内；Float 占 2
  "VarName": "LQT_NewTag",             // 全局唯一！不能与现有 VarName 重名
  "VarType": "Float",                  // Bool/Short/Int/UInt/Float/Double…
  "VarAddress": "1.40077",             // 人看的，不参与采集；保持与 Start 一致
  "Comments": "新增点说明",
  "Unit": "kPa",
  "Scale": 1.0, "Offset": 0.0,         // 目前不生效，仅占位
  "ArchiveEnable": true,               // 要历史曲线就 true
  "HighAlarmEnable": true, "HighAlarmValue": 80.0, "HighAlarmNote": "上限报警",
  "LowAlarmEnable": false, "AlarmDeadband": 0.5
}
```

3. 若新点超出原组范围：同步把该组 `Length` 调大；或新建一个组（`Start/Length` 不与现有组重叠为宜）。
4. 重启 App（或配置编辑器保存后按界面提示；字节序变更会回写文件）。

### 陷阱

- `VarName` 重名 → 历史库 `VarDict(VarName UNIQUE)` 把两路数据混成一条曲线，**不可逆地脏数据**。
- `Start` 写成"组内 0 起" → 与 02 篇第 4 节冲突；基址 100 的组变量要从 100 写。
- Float 的 `Start` 要预留 2 个寄存器（76、78…不要写 77 紧挨着另一个 Float）。
- `Length` 不够 → 越界读，整组 `NotCollected`/异常。

### 验证

- 页脚变量数 +1、归档/报警数按配置变化；实时表出现该行且质量"正常"。
- 跑 `KyjScada.Domain.Tests`（配置解析不炸）；开趋势查该 `VarName`（归档一轮后有点）。
- 制造越限值 → 报警页出现事件、`alarms.db` 有记录。

## 配方 2：新增一台 Modbus 设备

**目标**：同一种已支持协议（TCP / RTU / RTU-over-TCP）再接一台，并发采集、可切换查看。

### 改动

1. 在 `settings\` 新建或追加一个 JSON（`LoadDirectory` 会合并所有 `*.json`）。
   结构照 `ModbusRTUOverTCP.json`：顶层数组 → 项目 → 对应 `*List`（如 `ModbusTCPList`）里加设备对象。
2. 填 `DeviceName`（**全局唯一，决定 `ui_state` 记忆键和历史 `DeviceName`**）、连接参数、`DataFormat`、`Options`、`GroupList`。
3. `AppSettings` 无需改；多设备由 `AcquisitionCoordinator.Build(_deviceList)` 自动并发建流水线。

### 陷阱

- `DeviceName` 与现有设备同名 → `LoadDirectory` 合并/映射冲突，字节序回写可能写错文件。
- 协议键必须是 11 个规范键之一（`ModbusTCPList` 等），拼写错 → 该设备静默不加载。
- 串口设备：`PortName` 必须与设备管理器一致，且未被占用；`Baud/Parity/DataBits/StopBits` 要匹配。
- RTU-over-TCP 用的是 **RTU 帧无 MBAP**（`ModbusRTUOverTCP`），别配成 `ModbusTCP`。

### 验证

- 启动后设备下拉出现新设备；切过去能看到变量；切走后原设备仍在采（`OnAcqTick` 状态汇总不消失）。
- 新设备 `history.db` 归档的 `VarDict.DeviceName` 正确。

## 配方 3：接入一种新协议（有描述符但未实现采集 → 实现它）

**目标**：例如让 `ModbusASCII` 或 `Siemens` 从"· 未采集"变成真能采。

### 改动清单（按顺序）

| 步 | 层 | 文件 | 做什么 |
|---|---|---|---|
| 1 | Domain | `Protocol\*Descriptor.cs` | 确认/补全 `Key/DisplayName/ConnectionKind/Options/BuildAddress/Validate*`（已存在 11 个，通常只需补 `Options` 细节） |
| 2 | Domain | `Protocol\ProtocolKeyMap.cs` | `IsImplementedInV1` 加上该 key；家族判断按需补 |
| 3 | Domain | `Protocol\ProtocolRegistry.cs` | 新描述符在静态构造里 `Register(...)`（已注册的不用动） |
| 4 | Domain | `Config\SettingsJsonCodec.cs` | 若引入全新 `*List` 键，改 `CanonicalKeys` + `KeyToProtocol/ProtocolToKey`（**慎改，顺序影响往返**） |
| 5 | Infrastructure | `Modbus\` 或新建 `Xxx\` | 实现 `IModbusTransport`（或该协议自己的客户端）；帧编解码 + 连接 + 超时 |
| 6 | Infrastructure | `Acquisition\AcquisitionFactory.cs` | `IsCollectable`/`Create` 分支：按 `ProtocolKey` 返回对应 `IAcquisitionService` |
| 7 | Infrastructure | `Acquisition\...Service.cs` | 实现采集+（可选）写入；**失败必须 `NotCollected`+`Publish`，不抛**；复用 `IValueBus`/`IDeviceWriter` 语义 |
| 8 | Tests | `Domain.Tests\ProtocolTests.cs` | `BuildAddress`/校验用例 |
| 9 | Tests | `Infrastructure.Tests\...` | 帧编解码、模拟器/假 transport、`CollectOnce` 发布 `NotCollected` 的用例 |

### 陷阱

- 只改 `Descriptor` 不改 `AcquisitionFactory` → 界面仍显示"未采集"（`IsCollectable` 说了算）。
- 只改 `ProtocolKeyMap.IsImplementedInV1` 不给工厂实现 → 可能走到错误分支/抛异常。
- 地址规则若与现有 Modbus 不同，**不要**硬塞进 `ModbusAcquisitionService` 的 `Parse*`；新协议用自己的服务/解析，
  但 `BuildAddress`（Domain 侧显示/校验）也要同步实现。
- `SettingsJsonCodec.CanonicalKeys` 的顺序是老格式兼容的一部分，**追加放末尾**，不要重排。

### 验证

```powershell
.\KyjScada.Domain.Tests\bin\Debug\net8.0\KyjScada.Domain.Tests.exe          # 协议/解析
.\KyjScada.Infrastructure.Tests\bin\Debug\net8.0\KyjScada.Infrastructure.Tests.exe
```
再用模拟器/真机跑 App，确认：连接成功→"正常"、断线→`--` 且 `LastError` 可读、**不卡 UI**。

## 配方 4：新增报警判定规则（超出高/低/死区）

**目标**：例如速率报警、持续 N 秒越限、组合条件。

### 改动

| 层 | 文件 | 做什么 |
|---|---|---|
| Domain | `Alarm\` | 新建状态机（参照 `AlarmStateMachine`：`Update(value, at) → Transition?`，`null` 输入不改状态，带滞回/防抖，**独立状态位**） |
| Domain | `Config\ConfigModels.cs` + `SettingsJsonCodec.cs` | 新增配置字段（默认值 + 只在非默认时写 + `Clone` 复制 + 往返保真） |
| Runtime | `AlarmService.cs` | `BuildFrom` 为符合条件的变量实例化新状态机；`ProcessSnapshot` 喂值并汇总事件 |
| Contracts | `AlarmContracts.cs` | 若需要新方向/等级/展示字段，扩展（**影响所有实现与测试构造点**，谨慎） |
| Infrastructure | `Alarm\AlarmRepository.cs` | 若落库字段变了，改 DDL + `EnsureSchema` 幂等迁移 + 读写 SQL |
| MCP | `Data\DbReader.cs` / `Models.cs` | 同步报警查询（Mcp 无 Domain 引用，**必须手改**） |
| App | 报警页 XAML/CS | 展示新类型 |
| Tests | `Domain.Tests\AlarmTests.cs` 等 | 覆盖触发/消除/死区/空值/边界（尤其"阈值附近抖动"） |

### 陷阱

- **不要用"上一帧值比较"代替状态位**（04 篇 4 节的两次事故）。任何防抖/持续时间都要存在状态机内部。
- `AlarmEvent`/`ActiveAlarm` 改形状 → 全仓库构造点 + `AlarmRepository` + MCP + 报警页一起改。
- 新规则产出的 `At/Value` 语义要写清（`Reset` 产生的 `Value` 是 `NaN`，前例在先）。

## 配方 5：加一个界面 Tab / 页

### 改动

1. `MainWindow.xaml`：加 `TabItem`（抄现有风格：`Background="#1E1E2E" Foreground="#FFFFFF" FontSize="14"`），
   命名关键控件（`x:Name`）。
2. `MainWindow.xaml.cs` 或新建 `MainWindow.<Page>.cs`（partial，参考 `MainWindow.Jog.cs` / `Report.cs`）：
   `Init<Page>()`、事件处理、刷新方法；耗时查询走 `Task.Run` + `Dispatcher` 回 UI。
3. `ApplyDevice` 里调用 `Init<Page>()`（切设备要重建绑定）。
4. `OnUiTick` 里只做**轻量**刷新（目标 < 100 ms 总预算）；重活别放 500 ms tick。
5. 需要权限的按钮：在现有权限检查逻辑里加 `PermissionBit` 判断（07 篇第 8 节原则）。

### 陷阱

- 把数据库查询直接写在按钮 Click 的 UI 线程 → 界面卡死。
- 忘了在 `ApplyDevice` 里重绑 → 切设备后页面还显示旧设备数据。
- 用浅色控件但不设前景色 → 继承出白字/灰字看不清；参考 `App.xaml` 的 `TextStrong/FieldBg/BtnBg`。
- `ShowDialog` 子窗找不到 UIA 子树（见 07 篇 8 节 / 10 篇）。

## 配方 6：加一个 MCP 工具

### 改动

1. `KyjScada.Mcp\Tools\ReadOnlyTools.cs` 或 `WriteTools.cs`：加方法，打上 MCP SDK 的工具特性
   （参照现有方法的签名/特性/返回值序列化）。
2. 只读查库用 `DbReader`（`Mode=ReadOnly`）；查配置用 `ConfigReader`。**不要**打开可写连接。
3. 涉及写：**必须**走 `writeHandler` → `CommandGate`，`moduleId` 标清来源；绝不直连 transport。
4. `KyjScada.App\McpHost.cs` 的工具注册若按类型注册，确认新方法所在类已 `WithTools<T>()`。
5. `KyjScada.Mcp\Program.cs` 的 `--selftest`：加一条调用覆盖新工具（能连真库时）。
6. （可选但推荐）在 `Infrastructure.Tests\McpDbReaderTests.cs` 或新增测试里覆盖查询 SQL。

### 陷阱

- MCP 运行在 Kestrel 线程：碰 UI/`CommandGate` 必须 `Dispatcher.Invoke`（写工具已由 `McpWrite` 封装）。
- `DbReader` 自己写 SQL 且不引用 `HistorySchema` —— 加列/改表名要手同步。
- 返回给模型的文本要**明确、可解析**（含单位/时间/质量），别只回一个裸数字让 AI 猜。

## 配方 9：启用 `Scale/Offset`（当前未生效，改前必读）

现状：字段能存能显，**采集链路不乘**（02 篇第 11 节）。

正确落地方式（两边对称）：
1. `ModbusAcquisitionService` 解码得到原始值后、构造 `TagValue`/`Publish` 前：`eng = raw * Scale + Offset`。
2. `IDeviceWriter.WriteVariable` / `ModbusValueCodec` 编码前：`raw = (eng - Offset) / Scale`（注意 `Scale==0`）。
3. 回归：`WritePathTests`、`ModbusRtuTests`、`ArchiveServiceTests`；现场用已知点对比"设备示数 vs 界面"。

**只改读不改写 = 写下去回读值翻倍/错乱**，这是高危回归。
