# 14 无障碍与 UI 自动化（Accessibility & UIA）

> 面向：现场要接**读屏软件**、**工控机远程协助**，或要写 **UI 自动化测试**的人。
> 结论先说：这套界面**原本没有无障碍树**（大量控件在 UI Automation 里是"无名控件"），
> 现在已补齐到"每个可操作控件都有名字"。

## 1. 为什么工控上位机也要管无障碍

三个现实场景，跟"残障"关系不大，但都要求控件有名字：

| 场景 | 没有名字会怎样 |
|---|---|
| 现场用 Windows 讲述人/NVDA 辅助操作 | 读到"编辑框""按钮"，不知道是哪个，等于不能用 |
| 远程协助/录屏排障 | 自动化脚本点不到具体控件，只能靠坐标，换分辨率就废 |
| UI 自动化回归测试 | 只能用 `BoundingRectangle` 猜元素，脆弱到无法维护 |

全部通过 `AutomationProperties`（附加属性）声明，不动控件模板、不影响视觉：

| 变量搜索框（实时/历史/报警） | `实时监控变量搜索` / `历史趋势变量搜索` / `报警变量搜索` |

### 3.3 审计结果（改之后）

| 页签 | 无名可操作控件 |
|---|---|
| 实时监控 | 0 |
| 参数设置 | 4 → 仅剩滚动条模板里的 `RepeatButton`（`PART_LineUpButton` 等） |
| 急停/点动 | 0 |
| 报警 / 实时趋势 / 历史趋势 / 报表 | 0 |

剩下那 4 个是 `ScrollBar` 模板自带的翻行按钮，属于结构性部件，
读屏按"滚动条"角色处理，不需要（也不该）单独命名。

## 4. 怎么用

### 4.1 人工验证（读屏）

打开"讲述人"（Win+Ctrl+Enter）或用 NVDA，Tab 走一遍：
应该听到"用户名 编辑框""历史趋势分辨率 组合框""写1(开): LQB1_Start 按钮"这种完整表述。

### 4.2 自动化测试（PowerShell + UIA）

```powershell
Add-Type -AssemblyName UIAutomationClient,UIAutomationTypes

$p   = Get-Process KyjScada.App
$win = [System.Windows.Automation.AutomationElement]::RootElement.FindFirst(
    [System.Windows.Automation.TreeScope]::Children,
    (New-Object System.Windows.Automation.PropertyCondition(
        [System.Windows.Automation.AutomationElement]::ProcessIdProperty, $p.Id)))

# 按名字找控件（不再依赖坐标）
$tab = $win.FindFirst([System.Windows.Automation.TreeScope]::Descendants,
    (New-Object System.Windows.Automation.PropertyCondition(
        [System.Windows.Automation.AutomationElement]::NameProperty, '参数设置')))
$tab.GetCurrentPattern([System.Windows.Automation.SelectionItemPattern]::Pattern).Select()

$box = $win.FindFirst([System.Windows.Automation.TreeScope]::Descendants,
    (New-Object System.Windows.Automation.PropertyCondition(
        [System.Windows.Automation.AutomationElement]::NameProperty, '写入值: 冷却泵1频率给定')))
$box.GetCurrentPattern([System.Windows.Automation.ValuePattern]::Pattern).SetValue('35')
```

定位用 `Name`（人类可读）或 `AutomationId`（有显式声明的，如 `UserBox`）。

## 5. 新增控件时的规矩

1. **每个可交互控件都要有名字**：按钮用 `Content`（自动成为 Name），输入框/下拉框/曲线必须显式写
   `AutomationProperties.Name`。
2. **列表行内的控件，名字要带上行标识**（变量名），否则一排同名按钮对读屏毫无意义：
   ```xml
   <Button Content="写入"
           AutomationProperties.Name="{Binding VarName, StringFormat=写入: {0}}"/>
   ```
3. **不要用 `x:Name` 代替**：`x:Name` 只在代码里可见，UI Automation 读不到。
4. **图形/曲线**除了 Name，再给 `HelpText` 说明"数值请看哪里"——读屏读不出曲线趋势，
   必须告诉用户替代路径。
5. 新增窗口后，用第 2 节的统计方法复查一遍"无名可操作控件数"，应为 0。

## 6. 顺带落地的两项界面改进（同一提交）

| 改动 | 位置 | 说明 |
|---|---|---|
| 参数设置页显示**备注列** | `MainWindow.xaml` 参数设置 | 变量名多是 `LQB1_Fre_Set` 这类英文缩写，不显示中文描述就得靠背 |
| 写入前**差异确认** | `Runtime/WriteGuard.cs` | 输入值与当前值不同、或超出组态上下限时弹确认并标越界；一致则静默放行 |

`WriteGuard` 是纯函数、可单测（见 `Infrastructure.Tests` 的"写入差异校验"用例），
判定口径：值相同不打扰 → 值不同要确认 → 超上下限标"越界" → 组态没配范围时偏离 30% 也确认。
