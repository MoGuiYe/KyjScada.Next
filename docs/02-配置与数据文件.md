# 02 配置与数据文件

> **读者**：要改现场配置、要加设备/变量、要动数据库表、或者要搞懂"程序到底读哪个文件"的人。
> **读完能做到**：独立读懂 `settings\*.json` 的每个字段、知道程序会写哪些文件（以及什么时候写）、
> 改配置不把现场采集中断、改表结构知道要动几处。

⚠ **最容易犯的错**：去源码树里找 `settings\`。它不在源码里，只在**运行目录**：
`KyjScada.App\bin\Debug\net8.0-windows\settings\`。程序用 `AppContext.BaseDirectory` 作根。

## 1. 运行时目录：程序读什么、写什么

```
KyjScada.App\bin\Debug\net8.0-windows\
├─ KyjScada.App.exe                      ← 双击它
├─ settings\                             ← 只读（除"改字节序/配置编辑器保存"外）
│   ├─ ModbusTCP.json                    129 变量 / 35 归档 / 4 组
│   ├─ ModbusRTU.json                    139 变量 / 34 归档 / 4 组（串口 COM8 9600）
│   └─ ModbusRTUOverTCP.json             139 变量 / 36 归档 / 4 组（**当前在用**，127.0.0.1:502）
└─ data\
    ├─ history.db  (+ -wal, -shm)        历史长表，WAL 模式 ← 最大，会涨到 GB
    ├─ alarms.db                         报警事件
    ├─ users.db                          账号/权限（PBKDF2）
    ├─ app_settings.ini                  应用级设置（归档周期/保留/写入限速/班次/MCP）
    ├─ ui_state.ini                      记住"上次在看哪台设备"（1 行）
    ├─ trend_templates.ini               趋势模板（多组曲线预设）
    ├─ mcp_debug.log                     MCP 启停诊断（每次启动追加）
    └─ ui-latency.log                    仅 --ui-diag 时产生
```

| 文件 | 读的时机 | 写的时机 | 谁写 |
|---|---|---|---|
| `settings\*.json` | 启动 `OnLoaded`、配置编辑器打开 | 界面改字节序、配置编辑器「保存」 | `SettingsJsonCodec.SaveFile` / `TryUpdateDeviceWordOrder` |
| `app_settings.ini` | 启动一次 | 「系统设置」窗口保存 | `AppSettings.Save` |
| `ui_state.ini` | 启动 | 每次切设备 | `MainWindow.SaveUiState` |
| `trend_templates.ini` | 趋势页初始化 | 模板「保存/删除」 | `TrendTemplateStore` |
| `history.db` | 趋势/报表查询（读） | 归档线程每 10 s 批量写；每小时清理 | `ArchiveService` / `HistoryRepository` |
| `alarms.db` | 报警页、MCP | 采集线程的报警落库 | `AlarmRepository` |
| `users.db` | 登录、用户管理 | 用户管理窗口 | `UserRepository` |

## 2. `settings\*.json` 的顶层结构

一个文件 = 一个 JSON **数组**，数组里是若干个"项目"，每个项目用 **11 个固定键名** 分协议列设备：

```json
[
  {
    "ProjectName": "ModbusRTUOverTCP空压机",
    "SiemensList": [], "MelsecList": [], "MelsecFXSerialList": [],
    "OmronList": [], "OmronHostlinkList": [],
    "ModbusRTUList": [], "ModbusASCIIList": [], "ModbusTCPList": [],
    "ModbusRTUOverTCPList": [ { ...设备... } ],
    "OPCDAList": [], "OPCUAList": []
  }
]
```

**11 个规范键**（`SettingsJsonCodec.CanonicalKeys`，顺序与老文件一致，不要改顺序或增删）：

```
SiemensList  MelsecList  MelsecFXSerialList  OmronList  OmronHostlinkList
ModbusRTUList  ModbusASCIIList  ModbusTCPList  ModbusRTUOverTCPList
OPCDAList  OPCUAList
```

键名规则：`键 = 协议Key + "List"`（`KeyToProtocol` / `ProtocolToKey` 负责互转）。

### 三个坑（都在代码注释里有记录）

1. **文件里常有多余的"空壳项目"**：老编辑器遗留，顶层数组可能有 3 个对象但只有 1 个有设备。
   所以取配置必须用 `SettingsJsonCodec.ActiveProject(projects)`（返回第一个"有设备的"），
   **不要**直接 `projects[0]`。
2. **`LoadDirectory` 会合并整个目录**：一个目录下多个 JSON（每协议一个文件）会合并成一个 `ProjectConfig`，
   并按设备名建 `DeviceFiles` 字典（改字节序时知道写回哪个文件）。
3. **协议键可以缺失**：程序按 `CanonicalKeys` 找不到就跳过，不报错。新增协议键不会自动生效——
   要同时改 `CanonicalKeys` + `ProtocolRegistry`。

### 当前现场清单（实测，2026-11-06）

| 文件 | 项目名 | 设备名 | 连接 | 组数 | 变量 | 归档 | 高报 | 低报 | DataFormat |
|---|---|---|---|---|---|---|---|---|---|
| `ModbusTCP.json` | ModbusTCP空压机 | 空压机ModbusTCP | 127.0.0.1:502 | 4 | 129 | 35 | 4 | 3 | 缺省(ABCD) |
| `ModbusRTU.json` | ModbusRTU空压机 | ModbusRTU空压机 | COM8 9600,8,N,1 | 4 | 139 | 34 | 27 | 5 | 2 = CDAB |

## 3. 字段字典（改 JSON 前必读）

### 3.1 `DeviceConfig`（设备，`Config\ConfigModels.cs`）

| 字段 | 类型 | 默认 | 含义 | 坑 |
|---|---|---|---|---|
| `DeviceName` | string | `""` | 设备名，界面下拉显示 | **改名会丢掉 `ui_state.ini` 的记忆**，历史库 `VarDict.DeviceName` 也会变成新旧两套 |
| `IsActive` | bool | `true` | 是否启用 | 目前采集不看它（`Build` 也用），先别当开关用 |
| `ProtocolKey` | string | `""` | 协议键（不含 `List`） | 由 JSON 的键名推出来，**不要手写** |
| `IpAddress` / `Port` | string / int | — | TCP 端点 | RTU-over-TCP 也是 TCP，别把 `PortName` 写在这 |
| `PortName` | string | — | 串口名，如 `COM8` | 只在 `ConnectionKind.Serial` 用 |
| `BaudRate` `Parity` `DataBits` `StopBits` | int | 9600/0/8/1 | 串口参数 | `Parity` 是**数字**：0=None,1=Odd,2=Even |
| `DataFormat` | string | 缺省=ABCD | 多寄存器字节序：`0=ABCD 1=BADC 2=CDAB 3=DCBA` | 解析进 `WordOrder`，**不在 `Options` 里**；写回时原样保留 |
| `IsShortAddress` | string `"True"/"False"` | `"False"` | 短地址模式（40001 vs 400001） | 放在 `Options`（见 3.3），影响偏移 36 万 |
| `WordOrder` | enum | `Abcd` | 运行时表示 | 不是 JSON 字段，由 `DataFormat` 决定；界面改它 → 写回 `DataFormat` |
| `GroupList` | array | `[]` | 组列表 | 组是读取单位，顺序影响读取次数 |

### 3.2 `GroupConfig`（组）

| 字段 | 类型 | 默认 | 含义 |
|---|---|---|---|
| `GroupName` | string | `""` | 组名，**参与可写判定**（见第 6 节） |
| `IsActive` | bool | `true` | 是否采集该组 |
| `IsWritable` | bool | `false` | 是否开放写入；`true` 才写进 JSON（不写=不开放） |
| `Start` | string | — | 组起始地址，格式 `站号.区标识+偏移`，如 `1.400001` |
| `Length` | int | 0 | 组长度（寄存器/线圈个数） |
| `VarList` | array | `[]` | 组内变量 |

### 3.3 `VariableConfig`（变量）

| 字段 | 类型 | 默认 | 含义 | 备注 |
|---|---|---|---|---|
| `VarName` | string | `""` | 位号，**全局唯一**（历史库 `VarDict.VarName` 是 UNIQUE） | 改名等于丢历史（见第 9 节） |
| `VarType` | string | `Float` | `Bool/Byte/Short/UShort/Int/UInt/Float/Double/Long/String/ByteArray` | 决定占几个寄存器、能否写 |
| `VarAddress` | string | — | 给人看的绝对地址（如 `1.40001`） | **采集不用它**，只用于显示/导出 |
| `Start` | string | — | **绝对偏移**（与组的 `Start` 同一坐标系，如组的基址是 100，变量就从 100 写起）；空则回退解析 `VarAddress` | 三种写法：`100`＝纯偏移、`200.05`＝偏移.位号（**不是小数**）、`1.40101`＝站号.寄存器；见第 4 节 |
| `Comments` | string | — | 中文说明（报警注释、表格显示） | 别放参数（老系统就是拿它判短地址，出过 bug） |
| `Unit` | string | — | 工程单位 | 写进 `VarDict.Unit` |
| `Scale` / `Offset` | float | 1 / 0 | 比例/偏移 | ⚠ **当前采集链路不套用**（只存、只导出）。要启用见第 11 节 |
| `ArchiveEnable` | bool | false | 是否写历史 | 决定库容量，别乱开 |
| `HighAlarmEnable` `HighAlarmValue` `HighAlarmNote` | bool/float/string | false/0/— | 上限报警 | 判定在 `AlarmStateMachine` |
| `LowAlarmEnable` `LowAlarmValue` `LowAlarmNote` | bool/float/string | false/0/— | 下限报警 | 同上 |
| `AlarmDeadband` | float | 0 | 该点死区（覆盖全局） | 0 = 用 `app_settings.ini` 的全局死区 |

### 3.4 `Options`：老系统的"设备参数"袋子

`DeviceConfig.Options` 是 `Dictionary<string,string>`（大小写不敏感），键由**协议描述符**声明
（`IProtocolDescriptor.Options` → `OptionDefinition`），目前实际存在的：

| 协议 | Options 键 | 类型 | 默认 | 含义 |
|---|---|---|---|---|
| ModbusRTU / ASCII / RTU-over-TCP | `IsShortAddress` | Bool | `False` | 短地址（40001）还是长地址（400001） |
| 同上 | `CycleTimes` | Int | 3 | 轮询次数（重试） |
| 同上 | `CheckCycleTimes` | Int | 3 | 校验轮询次数 |
| ModbusTCP | `IsShortAddress` | Bool | `False` | 同上 |

为什么单独一个袋子：老系统把参数塞进 `Comments` 字符串，导致"中文备注被误判成短地址"。
代码里 `ParseDevice` 现在显式读 `Options`。

### 3.5 `ProjectConfig`

| 字段 | 含义 |
|---|---|
| `ProjectName` | 项目名（界面上不显示，日志/导出用） |

## 4. 地址是怎么算出来的（这是最容易配错的地方）

⚠ **先记住一句话**：组 `Start` 和变量 `Start` 用的是**同一个坐标系（绝对偏移）**。
组的 `1.400101` 已经把基准挪到 100，所以这个组里的变量必须从 `100` 开始写，**不是从 0**。
现场 4 个组就是这样：`0…` `/ 0…51` `/ 100…146` `/ 200…229`。

### 4.1 组地址：`站号.区标识+偏移` → 功能码 + 基址

代码在 `ModbusAcquisitionService.ParseGroupStart`（行 281），**不是**用 `IsShortAddress` 分支，
而是按数值区间判断（所以 `40001` 与 `400001` 两种写法都能解析）：

| 组 `Start` 数字段 | 功能码 | 基址（偏移 = n − 基址） | 现场用了吗 |
|---|---|---|---|
| `400001…465536` | 0x03 保持寄存器 | 400001 | ✅ `1.400001` → 0；`1.400101` → 100；`1.400201` → 200 |
| `40001…49999` | 0x03 保持寄存器 | 40001 | 老系统短地址写法 |
| `300001…365536` | 0x04 输入寄存器 | 300001 | — |
| `30001…39999` | 0x04 输入寄存器 | 30001 | — |
| `100001…165536` | 0x01 线圈 | 100001 | — |
| `10001…19999` | 0x01 线圈 | 10001 | — |
| `1…9999` | 0x01 线圈（1 基） | 1 | ✅ `1.000001` → 数字段 1 → 偏移 0（前导零被吃掉） |
| 其它 | ❌ 解析失败 | — | 该组全部点标记 `NotCollected`，`LastError` 记原因 |

> `1.000001` 看起来很怪，但按上表：`"000001"` → `int 1` → 落在 `1…9999` → 线圈、偏移 `1-1=0`。
> 这是"0 区"的老写法，别去"修"它。

### 4.2 变量地址：三种写法，一个坑

代码在 `ModbusAcquisitionService.TryParseVarAddress`（行 326）+ `NormalizeOffset/NormalizeRegister`。
`Start` 为空时会**回退去解析 `VarAddress`**（所以两处都空 = 该点不采集）。

| 写法 | 例子 | 解析结果 |
|---|---|---|
| 纯偏移 | `100` | 偏移 100（**绝对**，直接减组基址得到组内下标） |
| 完整地址 | `1.40101` | 第二段 ≥ 40001 → 当作"站号.寄存器"，`40101 → 100` |
| **偏移.位号** | `200.05` | 偏移 200 的**第 5 位**（`bit=5`），用于 Bool 挤在寄存器里的设备 |
| 带 `4xxxx` 前缀 | `40001` | 归一成偏移 0（不加归一会越界读不到） |

真正取数时：`rel = abs - baseOffset`，`rel < 0`（变量比组基址还小）→ 该点判失败。

### 4.3 Float 占 2 个寄存器

| `VarType` | 寄存器数 | 说明 |
|---|---|---|
| `Bool` | 线圈（0 寄存器） | 走 0x01/0x05，读出来是 bool |
| `Byte/SByte/Short/UShort/Word` | 1 | 16 位 |
| `Int/UInt/Float` | 2 | 32 位，跨两个寄存器 → **字节序（`DataFormat`）只对这类有意义** |
| `Double/Long/Int64/UInt64` | 4 | 能读；**不能写**（`RegisterCountForWrite` 返回 -1） |
| `String/ByteArray` | 不定 | 能读（按字节）；**不能写** |

### 4.4 ⚠ 同一套地址规则存在**两份实现**

| 用途 | 实现 | 位置 |
|---|---|---|
| **真正采集/写入** | `ParseGroupStart` / `TryParseVarAddress` | `Infrastructure\Acquisition\ModbusAcquisitionService.cs` |
| 显示/VarAddress 生成、配置校验、导出 | `BuildAddress` | `Domain\Protocol\*Descriptor.cs` → `ProtocolRegistry.BuildAddress` |

两份逻辑覆盖同样的写法，但**改地址规则必须同时改两处**，否则会出现
"配置校验说没问题、采集却读不到"。两边都有测试：
`KyjScada.Domain.Tests`（协议地址用例）与 `KyjScada.Infrastructure.Tests`（`WritePathTests`/`ModbusRtuTests`）。

### 4.5 不用开界面就能验证地址算得对不对

```powershell

.\KyjScada.Domain.Tests\bin\Debug\net8.0\KyjScada.Domain.Tests.exe
```

## 5. `app_settings.ini`（10 行键值，行首 `;` 是注释）

```ini
; KyjScada 应用设置(修改后重启生效)

RetentionDays=365            ; 历史保留天数（每小时清理一次）
```

| `ArchiveIntervalSeconds` | `ArchiveService.Interval` | 重启（流水线建时读取） |
| `RetentionDays` | `Archive.Purge` 的截止时间 | 重启；清理本身每小时最多跑一次 |

## 6. 可写规则（安全逻辑，别乱改）

一个点"能不能写"由**四层**叠加，全部通过才算可写：

```
① 组级：JogPoints.IsWritableGroup(group)
      group.IsWritable == true  优先
      否则组名包含 "设定"/"参数"/"Set"/"SP"  → 视为可写（老配置兜底）
      组名含"实时/状态/测量" 之类 → 不可写（代码里只做正例匹配，没有黑名单）
② 单点：CommandGate 的可写集合（构建时按 ① + 点位地址/类型再筛一遍）
③ 类型：ModbusValueCodec.RegisterCountForWrite
      Bool → 走线圈（返回 0）
      Byte/SByte/Short/UShort/Word → 1 个寄存器
      Int/UInt/Float → 2 个寄存器
      Double/Long/Int64/UInt64 → -1（"64 位暂不支持写入"）
      String/ByteArray → -1
④ 运行时：Enabled（界面勾选"允许写入"）+ 权限位 + 最小间隔 + 占用
```

**结论**：改 JSON 时把要写那个组的 `"IsWritable": true` 加上，或者把组名改成含"设定值"；
两者都没有 → 该组在「参数设置」「急停·点动」里不出现，MCP 写也会被拒（原因会回中文）。
当前三个现场 JSON 的组**都没有 `IsWritable`**，组名也没有"设定/参数"字样，
所以现场默认**没有可写点**（特性，不是 bug）。

## 8. 三个数据库（表结构 + 为什么这么设计）

### 8.1 `history.db` —— 长表（`Domain\History\HistorySchema.cs` 是唯一权威定义）

```sql
CREATE TABLE VarDict (
  VarId      INTEGER PRIMARY KEY,
  VarName    TEXT NOT NULL UNIQUE,
  DeviceName TEXT,
  Unit       TEXT
);
CREATE TABLE History (
  Id         INTEGER PRIMARY KEY AUTOINCREMENT,
  SampleTime TEXT NOT NULL,          -- 'yyyy-MM-dd HH:mm:ss' 本地时间（HistorySchema.TimeFormat）
  VarId      INTEGER NOT NULL,       -- → VarDict.VarId
  Value      REAL NOT NULL,          -- 只存有效值，绝不写 NULL
  Quality    INTEGER NOT NULL DEFAULT 0  -- 0=Good 1=非Good
);
CREATE INDEX idx_history_time       ON History(SampleTime);
CREATE INDEX idx_history_var_time   ON History(VarId, SampleTime);
```

为什么长表而不是老系统的宽表（`ActualData`，一列一个变量）：
- 加变量**不用 ALTER TABLE**（宽表加一列要重写整库）；
- 查询某几个变量只扫需要的行；
- 代价：每行都要带 `VarId` + 时间，单行开销略大，所以**只归档需要的变量**（现场 139 里 36 个）。

容量实测（代码注释里的估算）：`36 变量 × 10 秒 ≈ 6.5 GB/年`。调 `ArchiveIntervalSeconds` 或减少
`ArchiveEnable` 是唯一两个有效手段；`RetentionDays` 到期由 `ArchiveService.Purge` 删。

写库细节：`HistoryRepository.WritePoints` → 单事务批量 INSERT；`VarDict` 走内存缓存
（`_varIdCache`），不存在则 `GetOrCreateVarId` 插入。连接开 WAL + `synchronous=normal`。
**WAL 文件（`-wal`）在程序未正常关闭时会留着**，下次启动自动合并，不要手动删（删了丢最近数据）。

### 8.2 `alarms.db`（`Infrastructure\Alarm\AlarmRepository.cs`）

```sql
CREATE TABLE AlarmEvents (
  Id         INTEGER PRIMARY KEY AUTOINCREMENT,
  VarName    TEXT NOT NULL,
  Direction  INTEGER NOT NULL,   -- 0=High(上限) 1=Low(下限)
  IsTrigger  INTEGER NOT NULL,   -- 1=触发 0=消除
  Value      REAL NOT NULL,      -- 状态翻转时刻的采样值（消除事件记消除时值）
  OccurredAt TEXT NOT NULL,      -- ISO8601 本地时间
  WrittenAt  TEXT NOT NULL,      -- 落库时刻（诊断：能看出是否延迟写）
  AckAt      TEXT NULL           -- 确认时刻，NULL=未确认
);
CREATE INDEX IX_AlarmEvents_VarName_Time ON AlarmEvents(VarName, OccurredAt);
CREATE INDEX IX_AlarmEvents_Time         ON AlarmEvents(OccurredAt);
```

- `EnsureSchema` 兼容老库：**老版本没有 `AckAt` 列**，`CREATE TABLE IF NOT EXISTS` 不会补列，
  所以启动时会 `PRAGMA table_info` 检查并 `ALTER TABLE ADD COLUMN`（升级过库的人最容易忽略这里）。
- 一次报警 = 两行（触发 + 消除）；"当前报警"是"最新一条 IsTrigger=1 且没有对应消除"的推导结果，
  由 `AlarmService.GetActiveAlarms()` 在内存里算。
- 确认（`Acknowledge`/`AcknowledgeAll`）只改 `AckAt`，不改数据。

### 8.3 `users.db`（`Infrastructure\Users\UserRepository.cs`）

```sql
CREATE TABLE Users (
  Id           INTEGER PRIMARY KEY AUTOINCREMENT,
  UserName     TEXT NOT NULL UNIQUE,
  PasswordHash TEXT NOT NULL,   -- PBKDF2-SHA256, 32 字节 hex
  Salt         TEXT NOT NULL,   -- 16 字节 hex
  Iterations   INTEGER NOT NULL,-- 100000（PasswordHasher.Iterations）
  Permissions  INTEGER NOT NULL,-- 位掩码，见 04 篇 PermissionBit
  IsActive     INTEGER NOT NULL,
  CreatedAt    TEXT NOT NULL,
  LastLoginAt  TEXT
);
```

- 密码**永不落明文**；`PasswordHasher.Verify` 用记录里的 `Iterations` 重算（所以改迭代次数也能兼容老账号）。
- 种子账号：`admin / admin123`（`SeedDefaultAdmin`，只在库为空时建）。另有只读账号 `op1`。
- **不要**手工往这个表插密码哈希：`Salt/Iterations/Hash` 三者必须自洽，走界面或用
  `UserRepository.Create`。

## 10. 常见配置错误 → 症状对照

| 你写的 | 症状 | 修法 |
|---|---|---|
| `DataFormat` 漏写 | 浮点数读数离谱（如 50 → 8.5E-41 或巨大数） | 补 `"DataFormat": "2"`（现场是 CDAB） |
| `Start` 被当成"组内从 0 开始" | 组基址是 100/200 时全部错位：读到别组的寄存器，或 `rel<0` 直接判失败 | 变量 `Start` 写**绝对偏移**（组基址 100 → 变量就从 100 起） |
| `VarType` 与设备实际不符（Float 写 Short） | 数值像"天文数字"或恒为 0 | 按设备手册改类型；Float 占 2 寄存器，Short 占 1 |
| 两个 JSON 里同一个 `VarName` | 历史库两套数据混在一列（UNIQUE 只拦完全同名） | 位号全局唯一，加前缀区分 |
| 组 `Length` 小于变量实际跨度 | 越界读 → 整组失败，`State="异常"` | `Length` ≥ 最大偏移+类型长度 |
| 组 `Length` 大于设备实际区 | 设备回非法地址异常 → 整组读失败 | 按手册缩减 |
| 加了 `ArchiveEnable` 但库猛涨 | 正常（10 s 一次） | 调 `ArchiveIntervalSeconds` 或关掉不需要的点 |
| 加了可写组但按钮还是灰的 | 没登录/没权限/没勾"允许写入" | 用 `admin` 登录 → 「参数设置」页勾选 |
| `PortName` 写 `COM8` 但设备管理器是 `COM3` | `State="未连接"`，`LastError` 有"拒绝访问/找不到" | 改端口；串口被别的程序占用也会这样 |

## 11. 已知缺口（写代码前先看，别重复踩）

1. **`Scale`/`Offset` 不生效**：JSON 能读能写、配置编辑器能改、CSV 导出会带上，
   但 `ModbusAcquisitionService` 解码后**没有** `value * Scale + Offset`。
   要做工程量变换，正确改法是在解码入口（`ModbusAcquisitionService` 里取值后、`bus.Publish` 之前）
   统一套用，并在写方向做逆变换（`(value - Offset) / Scale`）——两边必须同时改，否则写下去的值回读会变样。
2. **`IsActive` 字段解析了但采集不用**：想让某组/某设备停采，目前只能从配置里删或改代码。
3. **`Options.CycleTimes/CheckCycleTimes` 声明了但采集实现未读取**（重试策略是写死的）。
4. **`ProjectName` 不参与任何逻辑**，只是标识。
5. **`VarAddress` 与 `Start` 可能不一致**：`VarAddress` 是人看的，采集只认 `Start`；
   改配置时若只改 `VarAddress`，现场表现为"地址改了但数据没变"。
