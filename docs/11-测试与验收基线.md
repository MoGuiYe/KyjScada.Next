# 11 测试与验收基线

> **读者**：要判断"我改完有没有回归"、要知道每个测试项目覆盖什么、要复现基线数字的人。
> **结论先行（2026-11-08 实测，Debug，net8.0，全量重建 `--no-incremental`）**：
>
> | 检查项 | 命令/产物 | 基线 |
> |---|---|---|
> | 全量构建 | `dotnet build KyjScada.Next.sln -v m` | **0 错误 / 124 条既有警告**（`App` 的 nullable、测试代码可空性提示；按文件与本轮改动前的基线完全一致，无新增） |
> | 领域测试 | `KyjScada.Domain.Tests.exe` | **43 通过 / 0 失败** |
> | 基础设施+运行时+MCP读库测试 | `KyjScada.Infrastructure.Tests.exe` | **323 通过 / 0 失败 / 1 跳过** |
> | 架构实证 | `KyjScada.Verify.exe` | **32 条断言全部 PASS**（7 个测试组），退出码 0 |
> | MCP 自检（需真库/配置） | `KyjScada.Mcp.exe --settings ... --db ... --selftest` | 9 个工具逐项 `OK/FAIL`（依赖环境数据） |

**改代码后的验收标准**：回到同样的通过数/退出码；若你新增了测试，用例数应**增加**而不是持平（持平可能是没编进新测试）。

## 1. 测试框架形态（重要）

- **不是** xUnit/NUnit/MSTest，**没有** `[Fact]`，`dotnet test` **不可用**。
- 两个测试项目都是 `OutputType Exe`，入口 `Program.cs` → `TestRunner.Run(name, Action)` → `Report()` 返回退出码。
- 断言：各项目自带 `Assert.cs` / `TestHelpers.cs`（`AssertEqual/AssertTrue/AssertThrows` 等风格，名字以文件为准）。
- 优点：无适配器依赖，`bin` 下 exe 直接跑；适合离线/现场机。缺点：没法在 IDE 测试资源管理器里一键发现（除非手配外部工具）。

## 4. `KyjScada.Verify`（7 组 / 32 条，架构实证）

**范围**：`IModule` 宿主契约与 `ValueBus/Runtime` 的结构性行为，纯内存。引用 `Contracts + Host + Runtime`。

| # | 名称 | 断言 |
|---|---|---|
| 1 | `IndependentRun` | 模块可独立加载并启动 |
| 2 | `FaultIsolation` | 单模块 `Init`/运行失败被隔离，不拖垮其他 |
| 3 | `DependencyCheck` | `Requires` 的服务缺失 → `Rejected`，不空引用崩溃 |
| 4 | `WriteConflict` | 写冲突/仲裁符合预期 |
| 5 | `NullSemantics` | `TagValue`/快照缺失（`null`）语义正确 |
| 6 | `SnapshotConsistency` | 快照不可变/版本一致性 |

**什么时候跑**：改了 `Contracts` 接口形状、`Host\ModuleHost`、`Runtime\ValueBus`、`CommandGate` 的并发/仲裁语义。
正式 App 不走 `IModule` 插件，但 Verify 是**防止架构回退成大泥球**的护栏。

## 5. MCP `--selftest`（集成烟雾，依赖环境）

```powershell
.\KyjScada.Mcp\bin\Debug\net8.0\KyjScada.Mcp.exe `
  --settings .\KyjScada.App\bin\Debug\net8.0-windows\settings `
  --db       .\KyjScada.App\bin\Debug\net8.0-windows\data\history.db `
  --selftest
```

依次调用：`ListVariables("LQT")`、`ReadVariable("LQT_Level")`、`QueryStat`、`QueryAlarms`、
`GetDeviceSummary`、`GetWriteStatus`、`WriteVariable("LQT_Level",50)` 等共 9 项，打印 `--- label OK/FAIL`。
- 需要**真实的 settings 目录和 history.db**（且库里有匹配数据）；空库/换设备名会 FAIL，但不代表代码错。
- `WriteVariable` 自检会真实走写链路（若连着写 handler/闸门配置），在生产库上慎跑。

## 6. 手工验收清单（UI/MCP/真机，自动化未覆盖）

| 场景 | 通过标准 |
|---|---|
| 启动 | 页脚显示设备/变量/报警/归档计数，无"启动失败" |
| 实时刷新 | 值 500 ms 级跳动，质量"正常"；`--ui-diag` 下 tick <100 ms |
| 断线 | 变量变 `--`/未采集，状态栏红色+可读原因；**不冻结旧值**；恢复后自动转绿 |
| 切设备 | 数据切换正确，**原设备仍采集**（状态汇总里还在） |
| 字节序 | Float 显示与设备一致（现场 `DataFormat=2`） |
| 报警 | 越限触发、回滞后消除；`alarms.db` 两条事件；确认后 `AckAt` 有值 |
| 历史趋势 | 查到曲线、游标读数正确、缩放/框选/导出 CSV 正常 |
| 报表 | 班次对齐、聚合、CSV 与 XLSX 都能打开 |
| 写入 | 登录+`CanWrite`+勾选启用+组可写 → 下发成功，`WriteResultText` 回显；未授权被拒绝且原因清楚 |
| MCP | `mcp_debug.log` 无异常、端口可 POST `/mcp`、只读工具返回与库一致、写入经闸门并在界面可见 |
| 主题对比度 | 7 个 Tab、选中 Tab 黑字、禁用按钮可读、下拉/输入框不塌高度、无白底白字 |
